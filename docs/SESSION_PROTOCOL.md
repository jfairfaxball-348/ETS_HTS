# Session protocol (binding)

## Entry / reconcile
A numbered session begins only after its owner-selected target has been separately installed in the authoritative prompt and state (`next_session_target_status=OWNER_TARGET_INSTALLED`) **and** the owner explicitly invokes that session. An uninstalled placeholder is not executable, even under a generic `run next session` request. A request to install/change a future target updates governance but is not session execution. Read GitHub live main and tree, enumerate all branches, PRs and session artefacts and inspect actual history, then compare with STATE, AGENTS, START_HERE and ledgers in that authority order. Conflicts are recorded, not overwritten. Establish the previous session as integrated or record a blocker, check this session number is unused and owner permission exists. Capture protected/ruleset reads and workflow/check-runs with scope and result; 403 = UNKNOWN, no check = ABSENT_NOT_PASS.

## Owner-driven target installation and session plan
The owner, not an assistant or automatic closeout, decides the next numbered target. On normal session completion, retain only a neutral `# S### — FUTURE / UNEXECUTED — TARGET NOT INSTALLED` placeholder; set `next_session_target_status=AWAITING_OWNER_TARGET`, `next_session_target=null`, `next_session_authorised=false`. An explicit instruction describing what to install changes that placeholder to the owner's substantive task and marks `OWNER_TARGET_INSTALLED`, but does not run it. A **new explicit owner invocation** is required after installation. When closing a session, do not suggest, choose or write a task for the following session. Keep open dependencies in the closeout as facts, not a next-session plan.

## Session plan
Record immutable input verbatim in sessions/S###/INPUT.md, tasks and exclusions in PLAN. One session branch from observed main SHA. Preregister every CAM before computation; assign sequential CND, SRC and CLM IDs. Exact source access grades are mandatory. Every mathematical claim must refer to a CLM entry or be plainly presented as tentative illustration. Preserve provenance and kills.

## Investigation phases
S001 is *solely* bootstrap. Future generation first uses mechanisms and tastes; novelty is shallow then deep, with literal query log, hit counts, dated source access and translations; difficulty uses recorded kill battery and bounded evidence. Do not infer from absence of evidence. Keep md/json catalogue pairs synchronized.

## Exit / integration
Run `python scripts/check_scaffold.py` and `python -m unittest discover -s tests -v` on an actual checkout; archive observed local results. Produce a coherent atomic **authored** proof commit; if hosted compilation finds an error, repair on the same branch with traceable additional ordinary commits, never force-push. For owner-targeted Lean sessions, continue proving further theorem-critical dependencies through repeated compile/repair cycles after any single successful lemma; stop only for full completion or a real resource/tool boundary, and report unresolved obligations **in the current closeout only**. Do not generate a substantive future-session handover or recommend follow-up work. Open an ordinary non-draft PR; attempt GitHub merge method `merge` only, not squash/rebase/force. Verify PR head, authored commit has one expected parent and tree, merge has two parents (old main then branch head), merge tree equals authored tree when no conflicts, and independently refetch main. Inspect job/check-run evidence separately from commit statuses. If merger or read fails, record exact failure and leave a truthful unmerged handoff. Never edit the committed closeout to insert future SHAs; record remote facts in PR/GitHub history and reconstruct next entry.

## Claims language
Use SOURCE_STATED for quotations/transcriptions inspected at an adequate access grade; PROGRAMME_PROVED only for a preserved proof with review; COMPUTED_EXACT for finite checked ranges only; HEURISTIC for models; INHERITED_UNVERIFIED otherwise. Checks cannot verify mathematics.
